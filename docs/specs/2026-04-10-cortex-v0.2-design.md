# Cortex Plugin v0.2 Design Spec

> Cortex 是一個 Obsidian vault + Claude Code plugin。
> vault 儲存個人工作記憶（Raw 原始記錄、Notes 技術知識、Projects 專案筆記、Weekly 週報）。
> plugin 提供自動記錄、手動存入、提煉、週報整理、檢索等功能。

## 1. 問題與目標

### 問題

- 開發過程中的知識、決策、工作紀錄散落在各 session 中，沒有集中保存
- 週報需要手動回想，容易漏記
- 資料量增長後（預期數千個檔案），簡單 Grep 搜尋不足以高效檢索
- 需要自動記錄但不能丟失重要資訊

### 目標

1. Session 結束時自動產出完整報告，包含 commits、發現、決策
2. 原始記錄保留完整（Raw/），提煉後的精華存到 Notes/Projects
3. 分層索引讓數千個檔案也能高效檢索
4. 週報從多個來源自動整理產出
5. 零外部依賴（純 markdown + JSON + git）

## 2. 架構概覽

### 雙 Branch 策略

同一個 repo（`git@git.synology.inc:tonyhu/cortex.git`）：

| Branch | 內容 | GitLab | GitHub |
|--------|------|--------|--------|
| `main` | vault 資料（Raw, Notes, Projects, Weekly） | ✗ | ✓ |
| `plugin` | plugin 程式碼（orphan branch） | ✓ | ✓ |

安裝方式：`/plugin marketplace add git@git.synology.inc:tonyhu/cortex.git#plugin`

### 本地設定

```
~/.cortex/
├── config.json              ← /cortex:genesis 產生
└── distill-state.json       ← distill 的本地快取（可從 Raw 重建）
```

### Vault 結構

```
cortex/

│   └── YYYY/MM/DD/
│       └── HHMMSS_session_<repo>.md
├── Notes/                   ← 提煉後的技術知識
│   ├── C++/
│   ├── DSM/
│   ├── Linux/
│   ├── Nginx/
│   └── Web/

│   └── <repo-name>/
│       ├── _index.md

│   ├── 2025/
│   └── 2026/
├── _index.md                ← LLM 維護的全 vault 摘要索引
```

## 3. 資料流

```
Claude Code session
    │
    ├── session 結束 ──→ [Stop hook]
    │                      └→ 回顧 session（包含所有 commits、發現、決策）
    │                      └→ 產出 session 報告草稿
    │                      └→ 詢問使用者確認
    │                      └→ Raw/YYYY/MM/DD/HHMMSS_session_<repo>.md
    │
    ├── 手動 ──→ [/cortex:evolve]
    │              └→ Notes/ 或 Projects/
    │              └→ 更新 _index.md
    │
    ├── 提煉 ──→ [/cortex:distill]
    │              └→ 讀 Raw/ 未處理的記錄
    │              └→ 提煉到 Notes/Projects
    │              └→ 標記 Raw（<!-- distilled: -->）
    │              └→ 更新 distill-state.json
    │              └→ 更新 _index.md
    │
    └── 週報 ──→ [/cortex:weekly]
                   └→ 呼叫 distill
                   └→ 拉 GitLab activity + CSS tickets
                   └→ 合併去重、分類
                   └→ 產出週報草稿讓使用者確認
                   └→ Weekly/YYYY/YYYY-MM-DD.md
```

## 4. 設定

### ~/.cortex/config.json

```json
{
  "vault_path": "/synosrc/misc/cortex",
  "author": "tonyhu",
  "author_email": "tonyhu@synology.com",
  "git": {
    "auto_commit": true,
    "auto_push": false
  },
  "weekly": {
    "gitlab_username": "tonyhu",
    "categories": ["fix", "feat", "misc"]
  }
}
```

優先順序：環境變數 `CORTEX_VAULT_PATH` > `config.json` > fallback `~/cortex`

### ~/.cortex/distill-state.json

```json
{
  "last_distill": "2026-04-10T09:00:00",
  "processed": [
    "Raw/2026/04/08/151032_session_dsm-AdminCenter.md",
    "Raw/2026/04/08/163045_session_redis-plus-plus.md"
  ]
}
```

此檔案是可重建的快取。Raw 檔案中的 `<!-- distilled: -->` 標記是 source of truth。

## 5. 元件設計

### 5.1 /cortex:genesis — 初始化

**觸發**：使用者首次設定，或換機器時

**流程**：

1. 檢查 `~/.cortex/config.json` 是否存在（存在則問是否重新設定）
2. 問 vault 路徑（或偵測現有 vault）
3. 問 author 資訊（name, email, GitLab username）
4. 寫 `~/.cortex/config.json`
5. 初始化 vault 結構（Raw/, Notes/, Projects/, Weekly/）
6. 初始化 git（如果沒有）
7. 偵測到現有 Raw/ 有內容 → 掃描 `<!-- distilled: -->` 標記 → 重建 `distill-state.json`
8. 偵測到現有 Notes/Projects/ 有內容 → 重建 `_index.md`
9. 建立 `.obsidianignore`（如果 plugin 在 vault 裡）
10. 顯示摘要

### 5.2 Stop Hook — Session 報告

**觸發**：Stop event（session 即將結束）

**類型**：prompt-based hook

**行為**：

1. 回顧 session 做了什麼（包含所有 commits、debug 過程、發現、決策、幫同事的事）
2. 產出 session 報告草稿
3. 展示給使用者確認（approve / edit / skip）
4. 同意後寫到 `<vault_path>/Raw/YYYY/MM/DD/HHMMSS_session_<repo>.md`
5. 在 vault repo 執行 git add + commit

**Session 報告格式**：

```markdown
---
date: 2026-04-08
time: "18:00"
type: session
repo: dsm-AdminCenter
tags:
  - nginx
  - FSDN
  - coverity
---

# Session: dsm-AdminCenter

## Commits

- fix(nginx): fix redirect in FSDN (DSM-123456, MR!1251)
- chore(test): update nginx redirect test cases

## 發現

- reverse proxy 在 FSDN 下 redirect 回 localhost，根因是 proxy_pass 用 Host 而非 X-Forwarded-Host
- synooauth 的 CSP 設定也有類似問題，但不在這次範圍

## 決策

- 改用 X-Forwarded-Host 替代 Host header

## 其他

- 幫 yukichen review coverity fix，scope 是 ignore

## 未完成

- wildcard cgi whitelist 還在 WIP
```

### 5.3 SessionStart Hook — 自動注入記憶

**觸發**：SessionStart event

**類型**：command hook（bash script）

**行為**：

1. 讀 `~/.cortex/config.json` 取 vault path
2. 如果 vault 不存在或沒 config → 靜默退出
3. 讀 `_index.md`
4. 從當前工作目錄推斷 repo 名
5. Grep match：Projects table 找 repo → 取出 tags → Notes table 找相同 tags
6. 輸出匹配的摘要行到 stdout（注入到 session context）

**輸出範例**：

```
[Cortex Memory] dsm-AdminCenter 相關記憶：
- Projects: login-portal, nginx, CSP | Login portal、reverse proxy、CSP 相關
- Notes: Reverse proxy remove in FSDN | proxy_pass Host→X-Fwd-Host fix
- Notes: Certificate | Let's Encrypt + ACME 流程
- 最近 Raw: 2026-04-08 nginx redirect fix + coverity review
```

### 5.4 /cortex:evolve — 手動存入

**觸發短語**：「存到 cortex」、「記一下」、「save to cortex」

**行為**：

1. 讀 `~/.cortex/config.json` 取 vault path（沒有則提示跑 genesis）
2. 判斷內容類型（Notes / Projects），不確定則問
3. 寫入檔案（Obsidian Flavored Markdown）
4. 更新 `_index.md`（append 一行到對應 section 的 table）
5. git add + commit

### 5.5 /cortex:distill — 提煉

**觸發短語**：「提煉」、「整理 raw」、「distill」

**行為**：

1. 讀 `~/.cortex/config.json` 取 vault path
2. 讀 `~/.cortex/distill-state.json`（本地快取）
3. Glob `Raw/` 所有檔案
4. 過濾已處理：
   - 在 distill-state.json → 跳過（快路徑）
   - 不在 → 讀檔案 grep `<!-- distilled:` 
     - 有標記 → 已處理，補進 distill-state.json
     - 沒標記 → 未處理，加入待處理清單
5. 對每個未處理的 Raw 檔案：
   - 讀取內容
   - 判斷是否有值得提煉到 Notes/Projects 的內容
   - 有 → 提煉並寫入，問使用者確認
   - 在 Raw 檔案末尾 append `<!-- distilled: YYYY-MM-DD → Notes/path.md -->`
6. 更新 `distill-state.json`
7. 更新 `_index.md`
8. git add + commit

### 5.6 /cortex:weekly — 週報整理

**觸發短語**：「整理週報」、「產生週報」、「weekly report」

**行為**：

1. 確定目標週（預設當週，可指定）
2. 呼叫 distill 處理該週的 Raw
3. 收集三個來源：
   - Raw/ 該週的所有檔案（已提煉 + 未提煉都讀）
   - GitLab activity（by `weekly.gitlab_username`）
   - CSS tickets（robinhood MCP `css_get_activities`）
4. 合併去重：
   - 同一個 MR 在 Raw 和 GitLab 都有 → 保留 Raw 的描述
   - GitLab 有但 Raw 沒有 → 補進來
5. 分類：fix / feat / misc
6. 產出草稿讓使用者確認
7. 寫到 `Weekly/YYYY/YYYY-MM-DD.md`
8. git add + commit

**週報格式**（維持現有）：

```markdown
---
title: "2026-04-06"
date: 2026-04-06
source: cortex
---

- fix.
	- [fix(nginx): fix redirect in FSDN](https://git.synology.inc/.../merge_requests/1251)
- feat.
	- [feat(sharing): 新增 FSDN access control](https://git.synology.inc/.../merge_requests/89)
- misc.
	- [css#3921519](https://cssnew.synology.com/ticket/3921519): 某問題 → 原因
	- yukichen(coverity): review coverity fix
```

### 5.7 /cortex:query — 搜尋

**觸發短語**：「查 cortex」、「之前有記過」、「cortex 裡有沒有」

**行為**：

1. 讀 `~/.cortex/config.json` 取 vault path
2. 先搜 `_index.md`（tags + summary grep）
3. 匹配到的條目 → 讀取對應檔案
4. 回傳結果，用 `[[wikilinks]]` 引用

## 7. Distill 狀態管理

**Source of truth**：Raw 檔案末尾的 HTML comment 標記

```markdown
<!-- distilled: 2026-04-10 → Notes/DSM/nginx-redirect-fsdn.md -->
```

**本地快取**：`~/.cortex/distill-state.json`

**衝突解決**：
- distill-state.json 裡有但 Raw 沒有標記 → 以 Raw 為準，重新處理
- distill-state.json 沒有但 Raw 有標記 → 補進 distill-state.json
- distill-state.json 丟失 → genesis 重建，或 distill 首次執行時自動重建

## 8. 典型使用節奏

```
每個 session：
  SessionStart hook → 自動注入相關記憶
  工作...
  session 結束 → Stop hook 產出報告 → 確認 → Raw/

隨時：
  /cortex:evolve → 手動存重要筆記到 Notes/Projects
  /cortex:query → 查之前的記錄
  /cortex:distill → 提煉 Raw 到 Notes/Projects

週五早上：
  /cortex:weekly → distill + GitLab + CSS → 週報
  git push → iMac/MacBook Obsidian 同步
```

## 9. 不在範圍內

- 向量資料庫 / 語意搜尋（未來可加 MCP server 擴展）
- 自動分類現有 Notes（維持現有結構）
- 遷移現有 Projects 結構（可手動遷移）
- iMac/MacBook 端的 plugin 安裝（那邊只用 Obsidian 看）
- MCP server（目前不需要）

## 10. 未來擴展

- MCP server 做語意搜尋（當 _index.md grep 不夠用時）
- 整合 graphify 建立 code 知識圖譜
- Lint 機制：定期檢查 orphan notes、過時條目
- 自動 git push（config 開關控制）
